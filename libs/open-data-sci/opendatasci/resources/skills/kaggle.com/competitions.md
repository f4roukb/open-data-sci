# kaggle.com — Navigating a Competition

- The **Data** tab is the source of truth for file schemas, column descriptions, and the train/test split rationale — read it before the overview page's prose, which tends to summarize loosely
- The **Leaderboard** tab's public score is computed on a subset of the test set (commonly ~20-30%); a high public rank late in a competition is not a reliable predictor of final private-leaderboard rank, so treat it as a noisy signal rather than the optimization target
- The **Code** tab (notebooks/kernels) sorted by "Most Votes" surfaces the community's best-validated starting points and EDA; sorted by "Most Recent" surfaces late-competition tricks and bug fixes that vote count hasn't caught up to yet — check both, not just one
- The **Discussion** tab concentrates the highest-density information in a competition's first days — data leaks, label errors, evaluation edge cases, host clarifications — and pinned/host posts should be read before general threads
- The submission format (column order, required precision, header expectations, prediction range) is stated on the **Overview → Evaluation** page and is part of the contract; mismatches cost ranked submissions
